# Запуск проекта на этом компьютере

Первоначальная настройка выполнена. Для обычной работы достаточно **start.cmd**
в папке LR_3. Можно запустить двойным щелчком из Проводника или выполнить:

```powershell
.\start.cmd
```

Если терминал открыт в корне itmo-web: `.\LR_3\start.cmd`.
Скрипт сам перейдёт в нужную папку.

## Адреса и вход

| Часть | Адрес/имя в текущей настройке |
|---|---|
| Сайт | http://127.0.0.1:5500/ |
| Java API | http://127.0.0.1:8081/api |
| Swagger | http://127.0.0.1:8081/swagger-ui.html |
| PostgreSQL | 127.0.0.1:55432, база students, пользователь students |
| Docker Compose | проект itmo-lr3, контейнер itmo-lr3-postgres-1 |
| ADMIN | имя admin; пароль в .runtime/admin-credentials.json |

Пароль не выводится в терминал. Открой `.runtime/admin-credentials.json` локально
и скопируй значение password в форму входа. Обычная регистрация создаёт USER,
который может просматривать студентов; ADMIN также изменяет данные.

На первом запуске скрипт выбрал доступный порт 8081 для Java. Точные параметры
сохраняются в server/.env. Адрес API для страниц генерируется статическим сервером
из этих параметров: редактировать config.js при таком запуске не нужно.

## Что делает start.cmd

1. Читает локальную конфигурацию и выбирает JDK 17+. На этом компьютере используется
   JDK из PyCharm; системная Java 8 не участвует в запуске проекта.
2. При необходимости запускает Docker Desktop и ждёт готовности engine.
3. Поднимает PostgreSQL только проекта itmo-lr3 и ждёт готовности БД. Образ
   postgres:17 уже загружен; первый download на новом компьютере может занять время.
4. При старте остановленного сервера собирает JAR, если изменились Java-код,
   ресурсы или pom.xml. Maven Wrapper скачивает зависимости при необходимости.
5. Запускает Spring Boot скрыто. Он выполняет миграции; скрипт ждёт readiness,
   включая завершение первоначальных действий.
6. Запускает локальный сервер HTML/CSS/JS на 5500 и открывает браузер.

Java и сервер страниц работают фоновыми процессами. Окно start.cmd после
успешного запуска может закрыться. Live Server дополнительно включать не нужно.
При повторном запуске start.cmd рабочие процессы не дублируются, браузер открывается
снова. После изменений Java сначала выполни stop.cmd, затем start.cmd; HTML/CSS/JS
читаются с диска при обновлении страницы.

Python нужен только для скрипта и статического сервера; backend лабораторной
реализован на Java. Node/npm для обычного запуска не нужны.

## Остановка и состояние

```powershell
.\stop.cmd
.\status.cmd
```

stop.cmd останавливает принадлежащие этой лабораторной Java/Python-процессы
и её PostgreSQL. Перед остановкой процесса проверяются PID и время создания,
чтобы не завершить постороннюю программу при повторном использовании PID.
Другие Compose-проекты не включаются в команды управления.

Том PostgreSQL сохраняется: остановка и новый запуск не очищают студентов,
пользователей и пароли. Docker Desktop остаётся доступным для других проектов.
status.cmd показывает состояние и оставляет окно открытым.

## Первоначальные данные

В PostgreSQL перенесены все **122 студента**. Для ИСУ 100097 по согласованию
исправлено ФИО на «Шестаков Илья Александрович». Исправление сделано в копии
для импорта; исходный students.json не менялся.

Импорт проверяет весь файл теми же серверными правилами до записи и выполняет
вставку в транзакции. Уже существующие ИСУ не перезаписываются. После успешного
первого импорта создаётся `.runtime/import-completed.json`, поэтому обычный
запуск не возвращает удалённых студентов и не затирает изменения.

Первый ADMIN создан с BCrypt-хешем. После успешного запуска автоматический bootstrap
выключен, пароль убран из bootstrap-параметра .env. Повторные старты не меняют
его учётную запись. Файл с данными входа остаётся локально для владельца проекта.

## Конфигурация, данные и логи

- `server/.env` — выбор JDK, порты, параметры БД и постоянный JWT-ключ.
- `.runtime/admin-credentials.json` — данные входа первого ADMIN.
- `.runtime/backend.log` — журнал Java.
- `.runtime/frontend.log` — журнал сервера страниц.
- `.runtime/build.log` — последний вывод сборки.
- `.runtime/import-report.json` — validated/imported/existing при первоначальном импорте.
- `.runtime/import-source.json` — контрольная сумма исходного JSON и согласованное исправление.
- `.runtime/processes.json` — данные процессов для точной остановки.
- Docker volume `itmo-lr3_students_pgdata` — постоянные данные PostgreSQL.

server/.env и .runtime исключены из Git. Статический сервер отдаёт только список
публичных файлов интерфейса: .env, пароли, исходный JSON, Java-код и служебные
папки по HTTP недоступны. Он слушает только 127.0.0.1.

Сохраняй .env вместе с локальной настройкой: в нём пароль БД и JWT-ключ.
Удаление .env не сбрасывает пароль уже созданной БД. Данные БД хранятся в Docker
volume, а не в старом db.sqlite3 и не в students.json.

Если появится ошибка, окно start.cmd останется открытым. Сначала посмотри указанное
сообщение и соответствующий log. Если порт занят другой программой, скрипт сообщает
об этом и не останавливает её. Для проверки без открытия браузера:

```powershell
python -X utf8 scripts/project.py start --no-browser
```

На другом компьютере первый запуск создаёт собственные случайные пароли/ключ,
находит установленный JDK 17+ и выбирает свободные порты. Нужны Python и Docker
Desktop с Linux containers. Постоянный том и локальные секреты не входят в Git.
