# Проверка шагов 1–10

Актуальная проверка выполнена 9 ноября 2026 года.

- JDK 17.0.7, Maven Wrapper / Maven 3.9.9.
- PostgreSQL 17.10: отдельный временный кластер на 127.0.0.1:55433,
  база students_it. Docker Desktop во время проверки не был запущен,
  поэтому использованы локальные PostgreSQL-бинарники из Maven Central
  (`io.zonky.test.postgres:embedded-postgres-binaries-windows-amd64:17.10.0`).
- Актуальный `mvnw.cmd verify`: BUILD SUCCESS, 11 модульных и 76 интеграционных тестов,
  без ошибок и пропусков.
- Flyway создал схему V1, затем применил V2 (Unicode-поиск студентов) и V3
  (Unicode-уникальность пользователей). Повторный запуск подтвердил контрольные
  суммы всех трёх миграций и отсутствие необходимости менять схему.
- Во время проверки исправлено отображение Instant: добавлен JPA-конвертер
  в JDBC Timestamp. Проверена запись и загрузка времени создания, истечения
  и отзыва токена с сохранением момента времени.
- Проверены CRUD, полное обновление PUT, PATCH с пропуском/очисткой полей,
  смена ИСУ без смены id, конфликты и отсутствие частичных изменений при ошибках.
- Проверены поиск по ФИО/заметкам на русском без учёта регистра, буквальные
  %, _ и обратная косая черта, сочетание фильтров с isForeigner=false,
  сортировка и стабильные страницы, пустая выборка и большой номер страницы.
- Проверены некорректные JSON/типы/даты/диапазоны, обязательные и связанные поля,
  ограничения ФИО/группы/заметок. Лимит заметок совпадает с PostgreSQL: 500 Unicode
  символов допустимы, 501 — нет, включая emoji.
- Проверены JSON-ошибки 400/401/403/404/405/406/409/415/422/429/500 и отсутствие
  SQL/стектрейса в ответах. Проверены DTO регистрации и предел пароля в байтах UTF-8.
- Проверены скользящее окно rate limit, параллельные запросы, Retry-After и
  невозможность обойти счётчик подменой X-Forwarded-For.
- StudentApiIT проверяет роли тестовыми пользователями Spring Security.
- AuthApiIT проверяет настоящие регистрацию/вход/JWT: BCrypt, принудительный USER
  при регистрации, уникальность имени/email, общий ответ неверного входа,
  ротацию и отзыв refresh, разделение назначения access/refresh, изменение подписи,
  истечение, issuer/audience/nbf, текущую роль БД, удалённого пользователя,
  неизменность bootstrap-аккаунта и CORS.
- StudentHttpIT запускает настоящий Tomcat на случайном порту: POST, QUERY,
  PATCH, PUT, GET, DELETE работают по HTTP, изменения фиксируются в PostgreSQL,
  а некорректный PATCH откатывается. Используется настоящий login и JWT, без
  разрешающей тестовой цепочки. Дополнительно проверены два одновременных
  запроса refresh: ровно один получает 200, второй — 401.
- При проверке основы шагов 1–4 собранный JAR также отдельно запускался на порту
  18083: health вернул 200 UP, а анонимный запрос к данным — 401. Эти проверки
  сохраняются в актуальных интеграционных тестах.
- После тестов таблицы students, app_users и refresh_tokens остались пустыми:
  транзакционные изменения откатились, запись HTTP-теста удалена его cleanup.
- Java-процесс и временный PostgreSQL после проверки остановлены.

## Браузер

`npm run test:e2e`: 6 тестов Playwright, все прошли. Установленный Chrome
запускался headless в отдельном контексте, без пользовательского профиля.
Статический HTTP-сервер слушал 127.0.0.1:5500, Java JAR — 18083, PostgreSQL —
55433. Использовались случайный тестовый JWT_SECRET и отдельная тестовая БД.

Проверены:

- редирект анонимного посетителя, регистрация и автоматический вход;
- USER: список, отсутствие кнопок изменения, защита прямого перехода к форме,
  настоящий отказ backend 403 без попытки refresh;
- ADMIN: создание, QUERY с фильтрами, сортировка, досье, редактирование ИСУ,
  удаление с подтверждением;
- истечение access при тестовом TTL 3 секунды: два параллельных запроса вызывают
  один refresh, получают 200, новый refresh сохраняется, старый отклоняется;
- продолжение сессии после перезагрузки страницы;
- отказ отозванного refresh с очисткой сессии и возвратом ко входу;
- временный сетевой сбой refresh: локальные данные сохраняются, повторная
  попытка восстанавливает работу;
- страница входа на ширине 390px без горизонтальной прокрутки; скриншот просмотрен.

Тестовые аккаунты e2e_reader_*/e2e-admin и их токены удалены после проверки.
Рабочий JWT_SECRET, постоянный ADMIN и пользовательская конфигурация запуска
в этой задаче не создавались.

Основные отчёты Maven находятся в target/surefire-reports и target/failsafe-reports
(каталог target не включается в Git). Инструкция для повторного запуска с
собственной PostgreSQL или Docker Compose есть в README.md.
