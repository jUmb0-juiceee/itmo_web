# Проверки данных в БД: замечания 1–2

V4 переводит app_users.role из VARCHAR в PostgreSQL ENUM user_role ('USER', 'ADMIN').
Java Role не изменён. RoleConverter передаёт PGobject с именованным типом через
EclipseLink. Драйвер PostgreSQL теперь нужен также при компиляции.

V5 добавляет недостающие ограничения. V1–V3 не изменены. При следующем запуске
Spring Boot Flyway применит миграции. Некорректные существующие строки остановят
миграцию, без автоматического удаления или исправления данных.

| Поле | Ограничения PostgreSQL |
|---|---|
| ИСУ | INTEGER, NOT NULL, UNIQUE, 100000–999999 |
| ФИО | NOT NULL, до 150 символов, три русских слова по шаблону Java |
| Группа | NOT NULL, до 10 символов, заглавная латинская буква и четыре цифры |
| Общежитие | NULL либо целое 1–999 |
| Комната | NULL либо целое 1–9999 |
| Дата заселения | NULL либо дата 2000-01-01–9999-12-31, без infinity |
| Заселение | Общежитие, комната, дата либо все заполнены, либо все NULL |
| Иностранец | BOOLEAN, NOT NULL, по умолчанию false |
| Заметки | NOT NULL, до 500 Unicode-символов, по умолчанию пустая строка |
| Логин | NOT NULL, 3–64 символа, шаблон Java, уникальность без учёта регистра |
| Email | NOT NULL, до 254 символов, непустые части вокруг единственного @ без пробелов; уникальность без учёта регистра |
| Хеш пароля | NOT NULL, формат BCrypt с допустимым cost и алфавитом |
| Роль | NOT NULL, ENUM USER/ADMIN, по умолчанию USER |
| Создание аккаунта | TIMESTAMPTZ, NOT NULL |
| Refresh ID | UUID, PRIMARY KEY |
| Владелец refresh | NOT NULL, внешний ключ на пользователя, ON DELETE CASCADE |
| Хеш refresh | NOT NULL, UNIQUE, 64 шестнадцатеричных символа |
| Даты refresh | Создание/истечение обязательны; истечение позже создания; отзыв NULL либо не раньше создания |

Большинство ограничений уже есть в V1. V5 добавляет формат ФИО, верхнюю границу
даты, формат/длину логина, структурную проверку email и формат хеша пароля.

## Границы дублирования

CHECK email — структурная проверка, не точная копия Jakarta @Email. Java также
проверяет локальную часть, домен и IDN. Необычные адреса в кавычках с пробелами
могут пройти @Email, но не CHECK. Полное совпадение требует согласования единого
допустимого формата email; сейчас проверка @Email остаётся в Java.

Длина исходного пароля проверяется в Java: БД получает только хеш. Проверки
JSON, фильтров, сортировки, прав и JWT не относятся к целостности хранимых полей.
Обрезка пробелов — нормализация перед сохранением.

## Проверки

DatabaseValidationIT проверяет прямые SQL-записи в обход Java-валидаторов,
границы диапазонов, 500 Unicode-символов, реальный тип роли, запись и чтение
обеих ролей через EclipseLink. Отдельная проверка обновляет схему V3 до V5
с существующим пользователем, студентом и refresh-сессией и проверяет их сохранность.

Полный Maven verify: 11 модульных и 102 интеграционных проверки, без ошибок.
Использовалась отдельная БД students_it. Рабочая база на этом этапе не менялась.
